## 1. Product in one paragraph
A free, shared home-management web app for Chris and his wife (Windows PCs, Samsung phone, iPhone). House: 353 Washington St, Canton MA, old house, one-pipe steam heat. Data lives in a Google Sheet, files in Google Drive, reminders in Google Calendar, all driven by a Google Apps Script web app owned by Chris. The front end is an installable PWA on GitHub Pages that holds no data of its own except a local cache. Manual entry only: no AI backend, no price scraping.

Priority order (Chris): 1 Maintenance scheduling, 2 Documents vault, 3 Room records. Deadline: a few days; Chris has about 2 hours per day for setup and testing.

## 2. Architecture
```
PWA (web/) --- fetch POST text/plain JSON ---> Apps Script web app (apps-script/)
  IndexedDB cache + outbox                      |-- Google Sheet (tabs = tables)
                                                |-- Drive folder "House Bible Files"
                                                |-- Calendar "House Bible"
                                                |-- Gmail alerts (weather)
```
- No build step, no npm dependencies in `web/`. Vanilla JS, ES modules allowed (`<script type="module">`), loaded from relative paths so GitHub Pages project sites work (never use absolute `/` paths).
- Apps Script is deployed as Web App: execute as owner, access "Anyone". It is protected by the shared key (section 4). Use `clasp` for deploys.
- Wife does not need Drive or Sheet access; she only needs the app URL and the key. (Chris may still share the Sheet with her to look at it.)

## 3. Data model (Google Sheet tabs)
Every tab's row 1 is the header. Every table has these system columns first, in this order:

`id, rev, updatedAt, updatedBy, deleted`

- `id`: client-generated, `crypto.randomUUID()` with the dashes removed (32 hex chars).
- `rev`: integer, assigned by the server on every accepted write, strictly increasing across the whole spreadsheet (one counter in Script Properties, guarded by LockService). Clients never set it.
- `updatedAt`: client epoch milliseconds when the user made the edit.
- `updatedBy`: free text device or person label, e.g. "Chris-phone".
- `deleted`: `0` or `1`. Deletes are soft. Never physically remove rows.

Fields below are typed: `text`, `num`, `date` (`YYYY-MM-DD`), `bool` (`0`/`1`), `json` (stringified), `ref:<table>` (an id), `files` (JSON array of file ids from the files API).

| Table | Fields |
|---|---|
| `rooms` | name, floor (text), length_in (num), width_in (num), height_in (num), flooring, wall_color, paint_notes, outlets, windows, notes, photos (files) |
| `assets` | name, kind (`system`\|`appliance`\|`fixture`\|`other`), room (ref:rooms), brand, model, serial, install_date, location, fuel, notes, warranty_expires (date), pro_only (bool), photos (files), docs (json array of document ids) |
| `shutoffs` | name, type (`water`\|`gas`\|`electric`\|`other`), room (ref:rooms), location, how_to, photos (files) |
| `tasks` | title, category (`house`\|`steam`\|`yard`\|`safety`\|`pet`\|`vehicle`\|`health`\|`other`), subject (text, e.g. dog name), rule (json, section 5), start (date), time (HH:MM), why, how, safety, pro_only (bool), asset (ref:assets), room (ref:rooms), assignee (text), calendar (bool, sync to Google Calendar), active (bool), source (`seed`\|`user`), seed_key (text, stable id for seeded tasks) |
| `task_log` | task (ref:tasks), date (date), by, note, cost (num), photos (files) |

Reserved: `settings` keys used by the system: `house` (address, lat, lon, year_built, sqft, floors), `alerts` (weather rules, section 6), `notify` (emails, calendar id), `schemaVersion`.

Adding a field later: add a column to the end of the tab and to `apps-script/schema.json`. Never reorder or rename columns. `schema.json` is the machine-readable copy of this table and is the source of truth the code reads.

## 4. API (Apps Script web app)
One URL: `POST <exec URL>`. Send `Content-Type: text/plain;charset=utf-8` with a JSON body (this avoids a CORS preflight, which Apps Script cannot answer). Follow redirects. Every response is JSON `{ok:true,...}` or `{ok:false,error:"code",message:"..."}`.

Every request body has: `{ "key": "<shared key>", "action": "...", "device": "Chris-phone", ... }`.
The key is checked against a SHA-256 hash in Script Properties. Wrong key returns `{ok:false,error:"auth"}` and never reveals anything else. Rate limit failed attempts is out of scope.

| action | request extra fields | response |
|---|---|---|
| `ping` | none | `{ok,serverTime,schemaVersion}` |
| `pull` | `since` (integer rev, 0 for everything) | `{ok,rev,tables:{name:[row,...]},more:false}` rows with `rev > since`, including deleted. If more than 2000 rows, set `more:true` and return the first 2000 by rev; the client repeats with the last `rev`. |
| `push` | `changes:[{table,row}]` (max 200) | `{ok,results:[{table,id,status,row}]}`. `status` is `accepted` or `stale`. Server keeps the row with the larger `updatedAt` (tie: server wins). Accepted rows come back with new `rev`. Stale rows come back with the winning server row so the client can overwrite its copy. |
| `upload` | `name,mime,dataBase64,parentKind` (`rooms`\|`assets`\|`documents`\|`general`) | `{ok,fileId,name,mime,size}`. Files land in Drive folder `House Bible Files/<parentKind>/`. Max 20 MB per call; the client must downscale images to max 1600 px JPEG quality 0.82 first. |
| `file` | `fileId` | `{ok,name,mime,dataBase64}` (max 20 MB). |
| `thumb` | `fileId` | `{ok,mime,dataBase64}` small JPEG preview (about 320 px) or a generic icon for non-images. |
| `syncCalendar` | none | Rebuilds Google Calendar events for tasks with `calendar=1` and `active=1`. Idempotent. `{ok,created,updated,removed}` |
| `testAlert` | none | Sends a sample weather alert email to the `notify` emails. |

Server rules:
- All writes inside `LockService.getScriptLock()` with a 20 second wait.
- Validate `table` against `schema.json`; ignore unknown fields; coerce types.
- Never delete rows or Drive files. `deleted` is the only delete.
- A `changelog` tab (hidden) records `{rev, table, id, updatedBy, at}` for each accepted write.
- Monthly time trigger copies the Spreadsheet to a "House Bible Backups" Drive folder, keeping the last 12.

## 5. Recurrence rule JSON (`tasks.rule`)
```
{"type":"yearly"}                                   // every year on `start` month and day
{"type":"monthly","interval":1}                     // every N months from `start`
{"type":"weekly","interval":1}                      // every N weeks from `start`
{"type":"days","interval":30}                       // every N days from `start` (use for pets and medication, e.g. heartworm every 30 days)
{"type":"seasonal","from":"MM-DD","to":"MM-DD"}     // window; due when inside it, repeating yearly
{"type":"once"}                                     // one time on `start`
{"type":"after_done","interval":90,"unit":"days"}   // next due is last completion + N (unit days|weeks|months|years)
```
Status computed on the client from `tasks` + `task_log`: `overdue` (past due, not logged), `due` (inside the window or within 7 days), `upcoming`, `done`. Completing a task writes a `task_log` row and, for `after_done`, moves the next due date. The reference implementation to port is `legacy/v1/js/util.js` (`occurrences`, `taskStatus`); S3 owns the new version in `web/js/core/recur.js` and must keep it pure (no DOM, no network) and unit tested with `node`.

## 6. Weather alerts (Apps Script time trigger, daily at 4 pm)
Source: National Weather Service `https://api.weather.gov` (free, no key; send a `User-Agent` with Chris's email). Location from `settings.house` lat/lon. Rules live in `settings.alerts` as `{rules:[{id,label,metric,op,value,hoursAhead,message,enabled}]}`. Metrics: `minTempF`, `maxTempF`, `snowIn`, `windMph`, `rainIn`. Defaults to ship disabled-off by default except freeze: `minTempF <= 28 within 48 h` with message "Freeze coming: drain/cover hose bibs, check exposed pipes." When a rule fires, send an email to `settings.notify.emails` and create an all-day Calendar event in "House Bible". De-duplicate: one alert per rule per day.

## 7. Sensitive data
Chris wants some sensitive items stored but protected. Design: client-side encryption. The `sensitive` tab only ever holds ciphertext. Key derivation: PBKDF2 (SHA-256, 250000 iterations) from a household passphrase plus a random per-install salt kept in `settings` key `crypto` (`{salt:base64}`), AES-GCM 256, random 12-byte IV per item. The passphrase is typed per device and kept in memory (optionally remembered in IndexedDB if the user ticks "remember on this device"). Lose the passphrase and the items are unrecoverable; say that in the UI. This protects against someone who gets into the Sheet; it does not protect against someone who has the passphrase. Passwords for accounts still belong in a password manager; the UI should say so.

## 8. Front-end module interface (what the other sessions code against)
All views are plain JS modules in `web/js/views/<name>.js`. Core is `web/js/core/*` (owned by S2).

```js
// web/js/core/data.js  (S2 owns; a working stub exists so views can be built now)
import * as HB from './data.js';
HB.list(table, {includeDeleted=false})  -> Promise<row[]>        // from local cache
HB.get(table, id)                       -> Promise<row|null>
HB.save(table, partialRow)              -> Promise<row>          // creates id if missing, sets updatedAt/updatedBy, queues push
HB.remove(table, id)                    -> Promise<void>         // soft delete
HB.subscribe(table, fn)                 -> unsubscribe           // fn(rows) on any local or remote change
HB.syncNow()                            -> Promise<{pushed,pulled,errors}>
HB.status()                             -> {online,pending,lastSync,syncing}
// web/js/core/files.js
HBFiles.upload(file|Blob, parentKind)   -> Promise<{fileId,name,mime,size}>   // downscales images, queues if offline
HBFiles.thumbUrl(fileId)                -> Promise<string>       // object URL, cached in IndexedDB
HBFiles.open(fileId)                    -> Promise<void>         // fetch + open/download
// web/js/core/ui.js  (S2 owns)
HBui.h(tag, attrs, ...children)         // DOM helper (port of legacy util.js h())
HBui.openForm(spec)                     // port of legacy openForm, add field types: ref (select from a table), files (photo/doc picker), json-list
HBui.toast(msg), HBui.confirm(msg)
// registering a view
import { registerView } from '../core/router.js';
registerView({ id:'maintenance', title:'Maintenance', icon:'wrench', order:10, render(container, ctx){ ... return cleanupFn } });
```
Styling: shared `web/css/tokens.css` and `web/css/base.css` (S2 owns). Views add their own `web/css/<view>.css` only. Use CSS tokens, never hard-coded colors; light and dark both work.

Mobile first: 375 px wide minimum, touch targets at least 44 px, no horizontal page scroll.

## 11. Changes in version 2 (made at integration)
- Section 4 `push`: a third result status `invalid` (with `message`) exists for rows that fail validation. It is permanent; the client does not retry it. (S1 request, implemented by S1 and S2.)
- Section 5: `weekly`, `monthly` and `days` rules accept optional `from` and `to` ("MM-DD") to limit occurrences to part of the year. Skip and snooze are stored as `task_log` notes (`[skipped] ...`, `[snoozed until YYYY-MM-DD] ...`). (S3.)
- Section 3: `assets.install_date` is `text`, not `date`, because old-house dates are approximate. `settings` key `crypto` holds `{salt, check}`. (S1, S4.)
- Section 3: project "tools needed" is stored in `projects.parts` as `{"tools":[...]}`; no new column. (S5.)
- Section 8: `data.js` also exports `callApi`, `deviceLabel`, `init`, `onStatus`, `addSyncHook`, `newId`, `reconfigure`; `files.js` also exports `blob(fileId)`. A `settings` view (house facts) was added at integration.
